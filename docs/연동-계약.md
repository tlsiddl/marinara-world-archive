# 연동 계약 — 세계관 설정집 ↔ 다른 모듈 (버전 1)

기억 서재(Memory Module) 같은 다른 모듈이 설정집을 읽고, 찾은 설정을 제안하는 통로입니다. 설정집은 다른 모듈 없이도 그대로 동작하고, 다른 모듈도 설정집이 없을 때 이 통로 없이 동작해야 합니다.

## ID

| ID | 뜻 | 모양 |
|---|---|---|
| `roomId` | 마리나라 채팅 ID(`chatId`) 그대로 | `^[A-Za-z0-9_-]{1,128}$` |
| `worldId` | 설정집의 세계관 ID. 방 하나는 세계관 하나를 읽음 | UUID |
| `entityId` | 세계관 안 설정 하나(인물·장소·집단·규칙·일정·기타) | UUID |

다른 모듈은 `roomId`로 묻고, 답에 들어 있는 `worldId` · `entityId`를 자기 쪽에 적어 두고 씁니다. 이름은 바뀔 수 있으니 ID로 묶습니다.

## 누가 무엇을 가지는지

- **설정집:** 오래 가는 설정 — 인물 · 장소 · 집단 · 규칙 · 일정의 칸, 다른 이름, 「지금 상태」(며칠 뒤에도 사실인 상태). 정본은 설정집 파일이고, 다른 모듈은 고치지 않고 제안만 합니다.
- **기억 서재:** 이야기에서 일어난 사건 · 기억 · 감정과 관계의 흐름 · 회상. 설정집은 사건을 저장하지 않습니다.
- **{{기억}}과 {{세계}}는 같은 내용을 두 번 넣지 않습니다.** {{세계}}는 설정만, {{기억}}은 사건과 기억만 넣습니다. 설정집에 있는 인물의 외형 · 성격 · 소속 같은 프로필을 {{기억}}이 다시 넣지 않고, 설정집은 「무슨 일이 있었는지」를 {{세계}}에 넣지 않습니다.

## 변경 제안(suggest) 규칙

- **기억 서재는 v1에서 suggest를 쓰지 않습니다**(사령탑 결정 2026-11-20). 설정집이 같은 방을 직접 읽으므로, 기억 서재까지 제안하면 같은 인물을 두 번 뽑아 토큰이 두 배가 되고 두 쪽이 다르게 쓰면 꼬입니다. 기억 서재는 `roomEntities` · `lookup`으로 받기만 합니다.
- **자동 반영이 켜진 세계관에만 씁니다.** 꺼져 있으면 아무것도 쓰지 않고 `{ written: false, reason: "automatic updates off" }`를 돌려줍니다.
- 설정집 자신의 자동 반영과 똑같이 씁니다: 없는 이름은 새 설정, 빈 칸은 채움, 자동으로 쓴 칸은 새 값으로 바꿈. **사람이 직접 쓴 칸(sources=manual)은 절대 덮어쓰지 않습니다.** 메모는 비어 있을 때만 씁니다.
- 바뀐 것은 모두 변경 기록에 `by`(보낸 모듈 이름)와 함께 남고, 화면 「기록」에서 하나씩 되돌릴 수 있습니다.
- 원문 근거를 확인하는 것은 보내는 모듈의 몫입니다. 확인된 것만 보내 주세요.

## HTTP (같은 서버의 브라우저 · 다른 프로그램)

모두 `/api/world-archive` 아래이고, 마리나라 자신의 접근 확인(로그인 · IP 허용 목록 · CSRF)을 그대로 거칩니다. 별도 토큰은 없습니다.

| 요청 | 답 |
|---|---|
| `GET rooms/:roomId/entities` | `{ worldId, entities: [설정] }` — 연결이 없으면 `{ worldId: null, entities: [] }` |
| `GET rooms/:roomId/lookup?name=…` | `{ worldId, entity: 설정 \| null }` — 이름이나 다른 이름이 같으면 찾음(대소문자 · 띄어쓰기 · 따옴표 무시, 이름 일부는 안 찾음) |
| `POST rooms/:roomId/suggest` `{ items: [항목], by: "memory-module" }` | `{ written: true, changes: [{ id, action, entityId, name, key? }] }` 또는 `{ written: false, reason: "no world" \| "automatic updates off", changes: [] }` |
| `GET rooms/:roomId/names` | `{ names: [{ original: "Severus Snape", translation: "세베루스 스네이프", kind: "인물" }] }` — 연결이 없으면 `{ names: [] }` |

- **설정:** `{ entityId, type, name, aliases, fields, description, pinned, sources, updatedAt }`. `type`은 `person · place · group · rule · schedule · custom`, `fields`의 칸 이름은 `GET /api/world-archive/status`의 `fields`에 있습니다.
- **항목:** `{ type, name, match?, aliases?, fields?: { 칸: "값" }, memo?, evidence?: "근거 문장", fieldEvidence?: { 칸: "근거 문장" } }`. 한 번에 50개까지, 근거는 300자까지 남습니다. `match`는 이미 있는 설정의 이름(다른 이름으로 부를 때). 모양이 틀린 항목 · 없는 칸은 조용히 건너뜁니다.
- **action:** `create`(새 설정) · `field`(칸) · `alias`(다른 이름) · `memo`(메모) · `rename`(번역 단어장을 따라 이름을 바꿈, `before` · `after`).
- **by:** 영어 소문자 · 숫자 · `-`로 40자까지. 없거나 틀리면 `module`로 남습니다. 설정집 자신의 읽기는 `reader`, 번역 단어장을 따른 이름 바꾸기는 `glossary`.
- **names:** 고유명사만 — 인물 · 장소 · 집단(`person · place · group`) 가운데 한글 이름과 로마자(라틴 문자) 다른 이름이 함께 있는 설정만 나옵니다. 규칙 · 시스템 · 일정 · 역사 · 기타는 나오지 않습니다(번역 단어장에 "Wandless, non-verbal Transfiguration = 변신술" 같은 쌍이 생기지 않게). `original`은 로마자 다른 이름 중 직함을 뺀 낱말이 가장 많은 것(같으면 긴 것), `translation`은 설정 이름, `kind`는 `인물 · 장소 · 집단` 가운데 하나. 번역 단어장을 따르는 이름은 단어장의 쌍 그대로 돌아오므로, 이 목록을 단어장에 더해도 다음 차례에 바뀌는 것이 없습니다.

## 번역 단어장(「번역 프리셋·단어장」)과 이름

- 설정집은 그 확장의 단어장을 **읽기만 합니다**(서버 안에서, 마리나라의 `GET /api/personal-extensions/:id/storage`와 같은 방법). 방의 `config.chats[roomId].glossary`, 없으면 `config.defaults.glossary`. 읽지 못하거나 glossary 칸이 없으면 아무것도 하지 않습니다(빈 단어장으로 치지 않음). 단어장에는 쓰지 않습니다.
- 자동 반영으로 읽을 때: 그 묶음에 나오는 쌍만 프롬프트에 넣고, 저장한 뒤 프로그램이 다시 확인해 단어장의 쌍이 설정의 **이름 전체**일 때만 이름을 단어장의 한국어로, 원래 표기는 다른 이름으로 둡니다(`rename`, 되돌릴 수 있음). 단어장이 바뀌면 이미 있는 설정도 맞춥니다.
  - 인물 · 장소 · 집단만 따릅니다. 다른 종류는 단어장으로 이름이 바뀌지 않습니다.
  - 이름 전체: 설정 이름이 쌍의 한국어와 같거나(이미 맞음), 설정 이름 또는 가장 긴 로마자 다른 이름(직함을 뺀 낱말이 가장 많은 것)이 쌍의 로마자와 같고, 쌍의 로마자 낱말 수가 그 가장 긴 로마자 다른 이름 이상일 때. 여러 쌍이 맞으면 낱말이 가장 많은 쌍.
  - 지금 이름의 일부로 줄이지 않습니다(「가스파르 셀윈」은 「가스파르」가 되지 않음).
  - 한 낱말 쌍(이름만 · 애칭, 예: `Gaspard = 가스파르`, `Bea = 비아`)은 여러 낱말 이름의 설정에서 이름이 되지 않고, 그 쌍의 한쪽이 다른 이름에 있을 때 빠진 쪽만 다른 이름으로 더합니다(`alias`, 다른 설정의 이름인 것은 더하지 않음).
- 사람이 직접 쓴 이름(직접 만든 설정, 이름을 고친 설정, 이름 바꾸기를 되돌린 설정)은 바꾸지 않고 설정에 `glossaryName`(제안)만 붙습니다. 다른 설정이 이미 그 이름이면 둘 다 그대로 두고 「같은 사람일 수 있음」에 맡깁니다.
- 오류: `roomId` 모양이 틀리면 400, 저장 파일이 손상됐으면 409(덮어쓰지 않음). 답은 `{ error: "한국어 설명" }`.

## 같은 서버 안 (preload 끼리, HTTP 없이)

```js
const wa = globalThis.__marinaraWorldArchive?.api;
if (wa?.version === 1) {
  wa.roomEntities(roomId);              // → HTTP entities와 같은 답
  wa.lookup(roomId, name);              // → HTTP lookup과 같은 답
  wa.suggest(roomId, items, 'memory-module'); // → HTTP suggest와 같은 답
  wa.names?.(roomId);                   // → HTTP names와 같은 답 (새로 더한 함수: 옛 설정집에는 없음)
}
```

- 네 함수 모두 바로 답합니다(Promise 아님). `roomId`가 틀리거나 연결이 없으면 빈 답을 돌려주고, 저장 파일이 손상됐을 때만 `status`가 붙은 오류를 던집니다.
- `api`가 없으면 설정집이 설치되지 않았거나 아직 서버에 붙기 전입니다. 그때는 설정집 없이 동작해 주세요.

## 연동 v2 (계약 수준 2 · 더하기만, `version: 1` 그대로)

설계: docs/연동-v2-설계안.md. 옛 기억 서재는 아래를 몰라도 그대로 동작합니다.

| 함수 / HTTP | 답 |
|---|---|
| `roomRelations(roomId)` / `GET rooms/:roomId/relations` | `{ worldId, relations: [{ relationId, from, to, fromName, toName, type, note, previous: [종류] }] }` — 두 끝이 모두 인물이고, 지금이나 전에(메모의 「과거에는 연인」) 가족 · 친구 · 연인 · 스승·제자 · 적대인 관계만. 소속 · 위치 · 기타만인 관계는 안 나옴 |
| `entity(roomId, entityId)` / `GET rooms/:roomId/entities/:entityId` | `{ worldId, entity: 설정 | null }` |
| `GET status` | 더해진 것: `contract: 2`, `features: ["relations", "species", "entity"]` |

- **api 객체:** `{ version: 1, contract: 2, features, roomEntities, lookup, suggest, names, roomRelations, entity }`. 다른 모듈은 `contract >= 2`로 새 함수가 있는지 봅니다.
- **인물의 `fields.species`(종):** 사람이 아닌 존재(고양이 · 부엉이 · 용 …)의 종만 적힙니다. **비어 있으면 「모름」**이지 사람이라는 뜻이 아닙니다. 설정집 읽기는 「사람」 같은 값을 적지 않습니다.
- **관계를 누가 바꾸나:** 설정집 읽기만. 다른 모듈은 관계를 읽기만 하고 보내지 않습니다(두 번 뽑지 않음). 「서로 아는 사이인지」는 설정집을, 「무엇을 아는지」는 기억 서재의 대화 정리를 따릅니다. 설정집 읽기는 6메시지마다라 늦을 수 있고, 다음 정리 때 맞춰집니다.

## 버전

지금은 `version: 1`. 답에 필드를 더하는 것은 같은 버전 안에서 합니다. 필드를 빼거나 뜻을 바꿀 때만 버전을 올리고, 그때는 이 문서에 둘의 차이를 적습니다.

## v0.5.0 덧붙임 (계약 2 그대로, features에 더함)

`status.features`: `relations` · `species` · `entity`에 `roster` · `timetable` · `calendar` · `appliesTo` · `base`가 더해졌다. 기존 필드는 그대로라 계약 번호(2)는 바뀌지 않는다. 새 필드는 모두 없을 수 있다(옛 자료).

- 설정 항목: `appliesTo`(규칙·시스템 — 장소·집단 id, `"world"` = 세계 전체, 없으면 모름) · `base`(집단의 본거지 장소 id) · `timetable` { ownerId, year?, cells{"월|1교시": {day, slot, value, subject?, place?, hours?, …}}, overlaps, wide } · `calendar` { ownerId|null, events{id: {date("YYYY-MM-DD" 또는 "--MM-DD"), name, place?, who?, cancelled?, past?, …}} } · `hidden`{칸: true}(프로필 블록에만 있는 칸) · `rumors`{칸: {value, by}} · `nameCheck`{said}.
- 명단: `GET /worlds/:id/entities/:groupId/members` → { members[{entityId, name, via, kind: member|staff|past, unnamed}], groups, counts }.
- 방: `GET /rooms/:id` → `story`{date, weekday}(이야기 속 오늘) · `latin`(영어 방).

## v0.5.1 덧붙임 (계약 2 그대로, features에 더함)

`status.features`에 `room`이 더해졌다. 기존 필드는 그대로라 계약 번호(2)는 바뀌지 않는다. 새 필드는 모두 없을 수 있다(옛 자료).

- 설정 항목: `room`(인물의 지내는 곳 — 장소 id) · `roomPast`[{placeId, until}](전에 지내던 곳, 3개까지) · `maybe`[{id, why}](자동 반영이 같은 것인지 헷갈린 설정 — 「같은 것일 수 있음」) · `seen`{n, last}(나온 묶음 수) · `extra`의 항목에 `source: "auto"`(자동 반영이 채운 균형 볼 칸). 집단 칸에 `size`(전체 인원).
- 명단 `counts`에 `known`(이름 아는 사람 · 지난 구성원 뺌) · `total`(전체 인원 칸을 코드가 읽은 수, 없으면 null).
- 세계관: `tail`{cast, balance}(`{{세계}}` 끝 두 줄 켜기/끄기, 없으면 켜짐) · `balance`[칸 이름](균형 볼 칸, 없으면 성별).
- `PUT /worlds/:id/entities/:personId/room` {room: 장소 id | null}. `GET /worlds/:id/duplicates`의 쌍에 `unsure: true`(헷갈림).
