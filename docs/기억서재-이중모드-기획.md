# 기억 서재 이중 모드 및 세계관 설정집 연동 개발 기획서

**프로젝트:** Marinara Memory & World System  
**대상 플랫폼:** Marinara Engine 2.5.2  
**기존 프로젝트:** `tlsiddl/marinara-memory-module`  
**개발 방향:** 기존 기능 보존 · 모듈화 · 선택적 기능 활성화 · 확장 간 연동  
**문서 상태:** 개발 기획 초안 v1.0

---

## 1. 프로젝트 개요

### 1.1 개발 목적

기존 기억 서재는 장기 롤플레이에서 인물의 경험, 과거 사건, 관계, 감정, 생활 기록 등을 관리하는 시스템이다.

그러나 봇카드가 특정 캐릭터가 아닌 내레이터 역할을 수행하는 세계 시뮬레이터에서는 기존 캐릭터 중심 구조만으로 세계 전체의 상태와 다수 NPC의 독립적인 활동을 관리하기 어렵다.

이를 해결하기 위해 다음 두 기능을 개발한다.

1. **기억 서재 이중 모드:** 기존 캐릭터 RP 모드와 신규 시뮬레이터 모드를 제공한다.
2. **세계관 설정집:** 세계의 지속적인 설정을 관리하는 독립 확장을 구축하고 기억 서재와 양방향으로 연동한다.

기존 기억 서재를 대체하거나 복제하지 않고 공통 기능을 재사용하는 방식으로 구현한다.

### 1.2 핵심 설계 원칙

- 기존 기억 서재의 기능과 데이터 호환성을 유지한다.
- 캐릭터 모드와 시뮬레이터 모드는 채팅방별로 선택한다.
- 시뮬레이터 모드에서는 봇카드를 실제 등장인물로 취급하지 않는다.
- 봇카드가 출력한 NPC 대사와 행동은 정상적으로 분석한다.
- 등장인물의 기억, 관계, 감정, 수첩 기능은 두 모드 모두 지원한다.
- 세계 설정과 실제로 발생한 사건을 구분한다.
- 두 확장은 독립적으로 작동할 수 있어야 한다.
- 사용하지 않는 기능은 비활성화하여 불필요한 모델 호출과 리소스 사용을 방지한다.
- 설정 변경 및 정보 동기화 과정에서 사용자의 직접 수정 내용을 보호한다.

## 2. 전체 시스템 구조

### 2.1 구성 요소

**A. 기억 서재 (Memory Archive)**

기존 확장을 유지하며 캐릭터 모드와 시뮬레이터 모드를 제공한다.

주요 역할:
- 장면 및 사건 정리
- 인물별 기억
- 감정과 관계 변화
- 비밀, 약속, 미해결 사건
- 인물별 수첩
- 현재 상태 및 생활 기록
- 과거 회상
- 세계에서 발생한 사건의 추적

**B. 세계관 설정집 (World Codex)**

별도 확장으로 개발한다.

주요 역할:
- 세계관 기본 정보
- NPC 기본 프로필
- 가문 및 조직
- 장소와 공간 구조
- 제도 및 규칙
- 반복 일정과 학사 일정
- 세계관 고유 시스템
- 지속적인 설정 변경 관리

**C. 공통 검색 및 연동 계층**

두 확장이 사용하는 정보 검색과 동기화 기능을 담당한다.

주요 역할:
- 공통 엔티티 ID 관리
- 인물 및 장소 별칭 연결
- 키워드 및 벡터 검색
- 변경 사항 전달
- 중복 검색 결과 제거
- 설정 충돌 감지
- 프롬프트 주입 예산 관리

공통 계층은 별도 프로세스를 반드시 요구하는 구조가 아니라, 필요한 기능만 호출할 수 있는 내부 모듈 또는 API 형태로 구현한다.

### 2.2 독립 실행 원칙

| 활성화 상태 | 동작 |
|---|---|
| 기억 서재만 활성화 | 기존 기억 기능 정상 작동 |
| 세계관 설정집만 활성화 | 설정 저장·검색·관리 가능 |
| 두 확장 모두 활성화 | 연동 및 통합 검색 활성화 |
| 두 확장 모두 비활성화 | 기본 마리나라 동작 유지 |

한쪽 확장의 오류 때문에 다른 확장이나 마리나라 본체가 중단되어서는 안 된다.

## 3. 기억 서재 이중 모드

### 3.1 캐릭터 모드

기존 기억 서재의 동작을 유지한다.

- 봇카드를 캐릭터로 인식한다.
- 기존 장면 정리와 회상 기능을 유지한다.
- 인물별 기억, 수첩, 관계, 감정을 관리한다.
- 기존 설정과 데이터 형식을 최대한 보존한다.
- 세계관 설정집이 연결된 경우 참고 정보를 검색할 수 있다.

기존 사용자에게는 기능 변경이나 추가 설정을 강제하지 않는다.

### 3.2 시뮬레이터 모드

봇카드를 특정 인물이 아닌 세계의 내레이터로 취급한다.

**봇카드 처리 규칙**

- 봇카드 자체를 NPC로 등록하지 않는다.
- 봇카드 이름으로 인물 기록이나 수첩을 생성하지 않는다.
- 내레이터의 서술을 특정 인물의 발언으로 취급하지 않는다.
- 내레이터가 출력한 NPC 대사는 실제 화자의 대사로 기록한다.
- 내레이터가 묘사한 행동과 사건은 해당 인물 또는 세계 사건으로 기록한다.
- 내레이터의 관찰·서술과 NPC 자신의 생각·지식을 구분한다.

**인물 관리 규칙**

- 등장하는 NPC를 개별 인물로 관리한다.
- 사용자 캐릭터도 세계 내 인물로 인식하되, 기존 사용자 캐릭터 처리 규칙을 유지한다.
- NPC마다 경험, 감정, 관계, 비밀 및 수첩을 독립적으로 기록한다.
- 등장하지 않는 NPC의 기존 기억도 보존한다.
- 현재 장면에 없다는 이유만으로 NPC를 삭제하거나 비활성 인물로 확정하지 않는다.

### 3.3 모드 설정 UI

기억 서재 설정에 다음 항목을 추가한다.

**기억 관리 모드**

- 캐릭터 RP
- 세계 시뮬레이터

설정은 채팅방별로 저장하며, 새로운 방의 기본값은 캐릭터 RP로 한다.

모드 변경 시 기존 기억을 삭제하지 않는다.

전환 시에는 인물 역할과 데이터 연결을 재검증한다. 과거에 잘못 생성된 내레이터 인물 기록이 있더라도 자동 삭제하지 않고 정리 후보로 표시한다.

## 4. 시뮬레이터 전용 기억 관리

### 4.1 기존 기능 유지

다음 기능은 새로운 시스템으로 다시 만들지 않고 기존 기억 서재를 활용한다.

- 장면 요약 및 사건 추출
- 챕터와 장기 서사 관리
- 인물별 기억
- 인물별 수첩
- 이름 및 별칭 정리
- 관계와 감정 기록
- 직접 선택한 기억
- 미해결 사건과 약속
- 현재 상태와 생활 기록
- 임베딩 검색 및 회상
- 직접 수정 및 수정 내용 보호

기존 기능의 데이터 모델이 시뮬레이터에 적합하지 않은 부분만 확장한다.

### 4.2 세계 사건 기록

시뮬레이터 모드에서는 개인의 경험 외에 세계 전체의 사건을 관리한다.

사건은 다음 정보를 포함할 수 있다.

- 사건 ID
- 발생 시각
- 발생 장소
- 참여 인물
- 관찰된 행동
- 확정된 결과
- 사건을 인지한 인물
- 관련된 세계 설정
- 원문 출처
- 확정 여부

이미 존재하는 장면 및 사건 기록과 중복 저장하지 않도록 기존 사건 ID를 참조한다.

### 4.3 NPC의 독립적인 활동

NPC는 사용자 캐릭터가 등장하지 않는 장면에서도 행동할 수 있다.

다만 기억 서재가 NPC의 행동을 임의로 확정해서는 안 된다.

다음 상태를 구분한다.

1. **확정 사건:** 실제 서사에서 발생했거나 사용자가 확정한 사건
2. **추정 상태:** 기존 기록으로 추론되지만 확정되지 않은 정보
3. **미확정 계획:** NPC가 하려고 했으나 아직 실행이 확인되지 않은 행동

예를 들어 NPC가 도서관에 갈 계획을 세웠다는 사실만으로 도서관 방문이 완료되었다고 기록하지 않는다.

장면 밖의 사건도 내레이터가 실제로 확정한 경우에만 정식 기록으로 반영한다.

### 4.4 인물별 지식 범위

시뮬레이터의 내레이터와 개별 NPC의 지식은 구분한다.

- 내레이터는 세계 사건 전체를 관리할 수 있다.
- NPC는 직접 경험하거나 전달받은 정보만 안다.
- 추측한 정보는 확정 지식과 구분한다.
- 비밀은 인물별 인지 상태를 기록한다.
- 정보 전달 사건이 발생하면 관련 인물의 지식 상태를 갱신한다.

**내레이터가 알고 있다는 이유만으로 NPC에게 비밀을 누설하지 않는다.**

## 5. 세계관 설정집

### 5.1 기본 기능

세계관 설정집은 지속적인 세계 정보를 구조적으로 저장하고 검색하는 독립 확장이다.

세계관별로 별도의 설정집을 생성할 수 있어야 한다.

하나의 설정집을 여러 채팅방에 연결할 수 있으며, 한 채팅방에서 발생한 사건이 다른 채팅방의 상태를 임의로 변경하지 않도록 한다.

### 5.2 정보 분류

| 분류 | 관리 정보 |
|---|---|
| 인물 | NPC 이름, 별칭, 외형, 성격, 기본 배경 |
| 집단 | 가문, 조직, 기숙사, 구성원 |
| 장소 | 공간, 구조, 위치, 출입구, 연결 관계 |
| 제도 | 규칙, 법률, 계급, 관습 |
| 일정 | 수업 시간표, 반복 행사, 학사 일정 |
| 역사 | 과거 사건, 세계관 연혁 |
| 시스템 | 마법, 능력, 점수, 경제 등 세계 고유 규칙 |

분류는 향후 확장 가능해야 하며 사용자 정의 항목도 지원할 수 있도록 설계한다.

### 5.3 설정의 상태와 우선순위

세계관 설정은 다음 유형으로 관리한다.

- **확정:** 사용자가 직접 작성하거나 승인한 설정
- **자동 기록:** 서사에서 추출되어 등록된 설정
- **검토 대기:** 아직 확정되지 않은 신규 설정
- **충돌:** 기존 정보와 모순되는 후보
- **폐기 또는 대체:** 유효하지 않게 된 과거 설정

사용자가 직접 확정한 정보는 AI가 자동으로 덮어쓸 수 없다.

설정 변경 이력과 이전 값을 저장하고 되돌리기를 지원한다.

## 6. 기억 서재와 세계관 설정집 연동

### 6.1 정보 소유권 분리

**기억 서재가 관리하는 정보**

- 실제 발생한 사건
- 인물의 경험
- 감정과 관계 변화
- 개인적인 비밀과 약속
- 현재 상태
- 인물별 기억과 수첩

**세계관 설정집이 관리하는 정보**

- 지속적인 기본 설정
- 세계 공통 규칙
- 인물의 신상 및 고정 속성
- 공간 구조와 소속 체계
- 반복 일정 및 제도

동일한 정보를 양쪽에 독립적으로 복제하지 않는다.

필요한 경우 원본 정보의 ID를 참조한다.

### 6.2 양방향 연동

**기억 서재 → 세계관 설정집**

서사에서 새로운 설정이 확정되면 세계관 설정집에 변경 후보를 전달한다.

예시:
- 새로운 NPC 등장
- 새로운 가문 또는 조직 등장
- 장소의 구조 확정
- NPC의 소속 변경
- 세계관 규칙의 추가 또는 수정

**세계관 설정집 → 기억 서재**

기억 서재는 인물 또는 사건을 분석할 때 세계관 설정집의 관련 정보를 참조할 수 있다.

예시:
- 인물 이름과 별칭 확인
- 가문 및 소속 확인
- 장소의 동일성 판단
- 기존 NPC와 신규 NPC 구별
- 사건과 세계관 규칙의 충돌 확인

세계관 설정집이 직접적인 경험이나 감정을 만들어 기억 서재에 삽입하지 않는다.

### 6.3 공통 엔티티 ID

두 확장은 동일한 NPC와 장소를 식별할 수 있어야 한다.

표시 이름 대신 안정적인 내부 ID를 사용한다.

예시:

`person:draco-malfoy`

이 ID에 다음 별칭을 연결한다.

- Draco Malfoy
- 드레이코 말포이
- 드레이코
- 말포이

동명이인과 서로 다른 시대의 인물은 이름만으로 자동 병합하지 않는다.

인물 별칭의 변경은 기존 기억 서재의 이름 정리 기능과 연동한다.

### 6.4 충돌 처리

두 확장에서 상충하는 정보가 발견되면 다음 원칙을 적용한다.

1. 원본 출처를 확인한다.
2. 정보의 적용 세계관과 채팅방을 확인한다.
3. 작중 시간에 따른 정상적인 변화인지 판단한다.
4. 실제 모순이라면 충돌 후보로 표시한다.
5. 확정된 설정은 사용자 승인 없이 변경하지 않는다.

예를 들어 NPC의 기숙사 소속이 기존 기록과 다르다면, 단순 오기인지 전학·이동 같은 사건인지 확인해야 한다.

### 6.5 연동 실패 처리

- 한쪽 확장이 비활성화되어도 다른 확장은 동작한다.
- 정보 연동 실패 시 기존 데이터를 삭제하지 않는다.
- 실패한 작업은 오류 상태와 함께 기록한다.
- 재시도 시 중복 인물이나 중복 항목이 생성되지 않아야 한다.
- 모델 호출 오류와 데이터 저장 오류를 구분한다.

## 7. 임베딩과 통합 검색

### 7.1 기존 검색 기능 재사용

기억 서재의 `vectors.cjs`에서 사용하는 기능을 최대한 활용한다.

- 코사인 유사도 검색
- 모델별 쿼리 전처리
- 검색어 분리
- 변경 텍스트 해시 검사
- 부분 재벡터화
- 검색 결과 순위 계산

단, 세계관 설정집과 기억 서재는 별도 검색 색인을 사용한다.

두 저장소가 동일한 임베딩 모델을 사용해야 하는 것은 아니다.

### 7.2 정보 종류별 검색 방식

| 정보 종류 | 우선 검색 방식 |
|---|---|
| 정확한 NPC 이름 | ID 및 별칭 일치 |
| 가문과 조직 | 키워드 + 구조적 필터 |
| 장소 | ID + 공간 연결 관계 |
| 과거 사건 | 벡터 검색 + 사건 연결 |
| 감정 및 관계 | 인물 ID + 관련 기억 |
| 세계관 규칙 | 키워드 + 벡터 검색 |
| 일정 | 구조화된 날짜 및 시간 조회 |

모든 정보를 단일 벡터 검색 결과 순위에만 의존하지 않는다.

### 7.3 통합 검색

현재 장면에서 다음 과정을 수행한다.

1. 등장인물과 장소를 식별한다.
2. 세계관 설정집에서 관련 기본 정보를 검색한다.
3. 기억 서재에서 관련 과거 사건과 상태를 검색한다.
4. 정보의 출처와 유효성을 검사한다.
5. 중복 항목을 제거한다.
6. NPC의 지식 범위를 적용한다.
7. 토큰 예산에 맞게 정보를 프롬프트에 전달한다.

### 7.4 토큰 사용량 관리

두 확장이 각각 모든 검색 결과를 프롬프트에 주입하지 않도록 한다.

공통 주입 단계에서 정보의 중요도와 우선순위를 평가한다.

우선순위 예시:

1. 현재 장면에 직접 필요한 확정 정보
2. 등장인물의 현재 상태
3. 관련된 과거 사건
4. 현재 상황에 적용되는 세계관 규칙
5. 간접적으로 관련된 참고 설정

검색 결과에는 출처 정보를 유지하되, 중복 본문을 반복 주입하지 않는다.

## 8. 세계관 및 채팅방 분리

### 8.1 세계관 단위 데이터

세계관 설정집의 공통 설정은 여러 채팅방에서 공유할 수 있다.

예시:

`world:hogwarts-1988`

해당 세계관에 연결된 여러 채팅방은 동일한 기본 NPC 및 장소 정보를 참조한다.

### 8.2 채팅방 단위 데이터

기억 서재의 사건과 인물 상태는 채팅방별로 관리한다.

서로 다른 채팅방에서 NPC가 다른 관계나 경험을 갖더라도 각 기록은 독립적으로 유지한다.

### 8.3 분기 처리

채팅방이 분기되면 다음 원칙을 적용한다.

- 분기 시점까지의 기억을 이어받는다.
- 이후 발생한 사건은 독립적으로 저장한다.
- 공통 세계관 설정집은 계속 참조할 수 있다.
- 세계관에 대한 채팅방 고유 변경은 별도 오버레이로 관리할 수 있게 설계한다.
- 한 분기의 변경이 다른 분기에 자동 전파되지 않는다.

기억 서재의 인물 상세 화면에서 세계관 설정집의 기본 프로필을 함께 볼 수 있도록 한다.

기억 서재의 기록과 설정집의 정보는 시각적으로 구분한다.

수정 버튼을 누르면 해당 정보를 실제로 소유하는 확장의 편집 화면으로 이동한다.

- 인물 상태 관리
- 임베딩 검색
- 세계관 데이터 연결
- 변경 감지 및 충돌 처리
- 프롬프트 주입

공통 기능은 중복 구현하지 않는다.

### 11.2 성능

- 사용하지 않는 모드의 처리 작업을 실행하지 않는다.
- 한 메시지의 원문을 불필요하게 여러 번 모델에 전달하지 않는다.

- 캐시와 색인 무효화 규칙을 명확히 한다.
- 메모리 사용량과 모델 호출 횟수를 측정할 수 있어야 한다.

기억 서재와 세계관 설정집이 동시에 활성화되어도 서버의 메모리 사용량이 지속적으로 증가하지 않도록 검증한다.

## 12. 데이터 안정성

### 12.1 기존 데이터 보호

- 기존 기억 서재 데이터를 삭제하지 않는다.
- 모드 변경으로 기존 기록을 덮어쓰지 않는다.
- 직접 수정한 기록은 자동 업데이트로 변경하지 않는다.
- 데이터 형식 변경 시 마이그레이션을 제공한다.
- 마이그레이션 전 백업을 생성한다.
- 실패 시 이전 상태로 복구할 수 있어야 한다.

### 12.2 변경 이력

세계관 설정집의 자동 변경과 직접 변경을 구분한다.

각 변경에는 다음 정보를 저장한다.

- 변경 시각
- 변경 주체
- 원본 출처
- 이전 값
- 새로운 값
- 승인 상태

### 12.3 삭제 처리

NPC나 장소를 삭제할 때 연동된 기억까지 즉시 삭제하지 않는다.

참조 관계를 확인하고 사용자에게 영향 범위를 표시한다.

- 중복 및 충돌 검증
- 통합 검색

### 5단계: 시뮬레이터 고급 기능

- 세계 사건 관리 강화
- NPC 독립 활동 기록
- 인물별 지식 범위 추적
- 미확정 사건 처리
- 세계 상태 변화 추적
- 분기별 상태 분리

**완료 기준:** 장시간 진행하는 시뮬레이터에서도 세계 상태와 NPC 기억의 일관성이 유지됨.

## 14. 필수 검증 시나리오

### 테스트 A: 내레이터 제외

봇카드 이름이 `Hogwarts Simulator`인 상태에서 NPC 여러 명이 등장한다.

예상 결과:
- Hogwarts Simulator 인물은 생성되지 않음
- 등장한 NPC들은 정상 등록됨
- 각 NPC의 발언과 사건이 구분되어 기록됨

### 테스트 B: 인물 기억 유지

NPC A가 NPC B에게 비밀을 전달한다.

예상 결과:
- NPC A와 B가 해당 비밀을 인지함
- 다른 NPC는 자동으로 알지 못함
- 내레이터는 세계 사건으로 사실을 관리함

### 테스트 C: 세계관 설정 연동

새로운 NPC가 등장하고 기숙사와 가문이 확정된다.

예상 결과:
- 기억 서재에서 인물 식별
- 세계관 설정집에서 중복 여부 확인
- 신규 프로필 등록 제안
- 승인 후 두 확장이 동일한 인물 ID 참조

### 테스트 D: 설정 충돌

기존 NPC의 소속과 다른 정보가 서사에서 등장한다.

예상 결과:
- 즉시 기존 설정을 덮어쓰지 않음
- 정상적인 변화인지 모순인지 검토
- 충돌 또는 변경 후보로 표시

### 테스트 E: 모드 전환

기존 캐릭터 RP 채팅방을 시뮬레이터 모드로 변경한다.

예상 결과:
- 기존 기억 보존
- 새로운 모드 규칙 적용
- 내레이터 역할 재해석
- 기존 NPC 및 사용자 기록 유지

### 테스트 F: 확장 비활성화

세계관 설정집을 비활성화한 상태에서 기억 서재를 사용한다.

예상 결과:
- 기억 서재 독립 동작
- 데이터 손실 없음
- 불필요한 세계관 검색 호출 없음

### 테스트 G: 장시간 사용

NPC 수와 사건 기록이 지속적으로 증가하는 장시간 채팅을 진행한다.

예상 결과:
- 검색 결과의 품질 유지
- 불필요한 전체 색인 재생성 방지
- 메모리 누수 및 중복 모델 호출 없음
- 데이터 충돌 및 중복 인물 생성 방지

## 15. 비목표 및 개발 제한

- 기존 기억 서재 전체 구조의 재작성

이 기능들은 기본 구조가 안정화된 이후 별도로 검토한다.

## 16. 최종 개발 목표

본 프로젝트의 핵심은 기억 서재와 세계관 설정집을 경쟁하는 두 시스템으로 만드는 것이 아니라, 서로 다른 종류의 정보를 담당하는 상호 보완 시스템으로 구축하는 것이다.

**기억 서재는 인물의 경험과 세계에서 실제로 발생한 사건을 관리한다.**

**세계관 설정집은 세계의 지속적인 설정, 구조, 규칙을 관리한다.**

캐릭터 모드에서는 기존의 개인 중심 장기 기억 기능을 유지한다.

시뮬레이터 모드에서는 봇카드를 내레이터로 취급하면서, 모든 등장인물이 독립적인 기억과 관계를 가질 수 있도록 한다.

두 시스템의 연동은 정보의 중복을 최소화하고, 직접 확정한 설정을 보호하며, 필요한 순간에 적절한 정보를 검색하는 데 목적을 둔다.

최종적으로 장기 롤플레이와 다수 NPC 기반 세계 시뮬레이션을 모두 지원하는 확장 가능한 기억·세계관 관리 구조를 완성한다.
